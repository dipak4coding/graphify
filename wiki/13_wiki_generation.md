## What This Module Does

`wiki.py` generates a **Wikipedia-style wiki** from the knowledge graph — a set of linked markdown files that an AI agent can navigate to understand the codebase without reading every raw file.

The wiki is structured like an encyclopedia:
- `index.md` — the front page, linking to all communities and god nodes
- One article per community — describes what that architectural cluster contains
- One article per god node — detailed page for the most-connected concepts

This is different from the Obsidian vault export (`export.py`): the wiki is designed to be navigated by AI agents, not by humans in a note-taking app.

## The Three Article Types

### 1. index.md — The Entry Point

```python
def _index_md(communities, labels, god_nodes_data, total_nodes, total_edges) -> str:
    lines = [
        "# Knowledge Graph Index",
        "",
        "> Auto-generated by graphify. Start here.",
        "",
        f"**{total_nodes} nodes · {total_edges} edges · {len(communities)} communities**",
        "",
        "## Communities",
        "(sorted by size, largest first)",
    ]
    for cid, nodes in sorted(communities.items(), key=lambda x: -len(x[1])):
        label = labels.get(cid, f"Community {cid}")
        lines.append(f"- [[{label}]] — {len(nodes)} nodes")
    
    if god_nodes_data:
        lines += ["## God Nodes", "(most connected concepts)", ""]
        for node in god_nodes_data:
            lines.append(f"- [[{node['label']}]] — {node['edges']} connections")
    ...
```

The `[[label]]` syntax is Obsidian wikilink syntax — click it to navigate to the linked article. In plain markdown viewers, it shows as `[[label]]`. In Obsidian, it's a clickable link.

**Relationships section (cross-community links):**
```python
def _cross_community_links(G, nodes, own_cid, labels) -> list[tuple[str, int]]:
    counts = Counter()
    for nid in nodes:
        for neighbor in G.neighbors(nid):
            ncid = G.nodes[neighbor].get("community")
            if ncid is not None and ncid != own_cid:
                counts[labels.get(ncid, f"Community {ncid}")] += 1
    return sorted(counts.items(), key=lambda x: -x[1])
```

For each node in the community, count how many of its neighbors are in other communities. Group by other-community and sort descending. This tells you: "this community mostly talks to the Authentication community (12 shared edges) and the Database community (8 shared edges)."

### 3. God Node Articles — One Per Most-Connected Node

```python
def _god_node_article(G, nid, labels) -> str:
    d = G.nodes[nid]
    node_label = d.get("label", nid)
    
    # Group neighbors by relation type
    by_relation = {}
    for neighbor in sorted(G.neighbors(nid), key=lambda n: G.degree(n), reverse=True):
        ed = G.edges[nid, neighbor]
        rel = ed.get("relation", "related")
        neighbor_label = G.nodes[neighbor].get("label", neighbor)
        conf = ed.get("confidence", "")
        conf_str = f" `{conf}`" if conf else ""
        by_relation.setdefault(rel, []).append(f"[[{neighbor_label}]]{conf_str}")
    
    lines = [f"# {node_label}", "", f"> God node · {G.degree(nid)} connections · `{src}`", ""]
    
    lines += ["## Connections by Relation", ""]
    for rel, targets in sorted(by_relation.items()):
        lines.append(f"### {rel}")
        for t in targets[:20]:
            lines.append(f"- {t}")
```

God node articles group connections by relation type:
```markdown
### calls
- [[fetch_data()]] `EXTRACTED`
- [[validate_input()]] `EXTRACTED`

### imports
- [[requests]] `EXTRACTED`
```

Each connection is a wikilink — click to navigate to that node's article (if it has one) or the community article that contains it.

## to_wiki() — The Main Function

```python
def to_wiki(
    G: nx.Graph,
    communities: dict[int, list[str]],
    output_dir: str | Path,
    community_labels: dict[int, str] | None = None,
    cohesion: dict[int, float] | None = None,
    god_nodes_data: list[dict] | None = None,
) -> int:
    out = Path(output_dir)
    out.mkdir(parents=True, exist_ok=True)

    count = 0

    # Community articles
    for cid, nodes in communities.items():
        label = labels.get(cid, f"Community {cid}")
        article = _community_article(G, cid, nodes, label, labels, cohesion.get(cid))
        (out / f"{_safe_filename(label)}.md").write_text(article)
        count += 1

    # God node articles
    for node_data in god_nodes_data:
        nid = node_data.get("id")
        if nid and nid in G:
            article = _god_node_article(G, nid, labels)
            (out / f"{_safe_filename(node_data['label'])}.md").write_text(article)
            count += 1

    # Index
    (out / "index.md").write_text(_index_md(...))

    return count  # number of articles written (excluding index)
```

Files are written with `_safe_filename()` as the name:

```python
def _safe_filename(name: str) -> str:
    return name.replace("/", "-").replace(" ", "_").replace(":", "-")
```

`"Attention Mechanism"` → `"Attention_Mechanism.md"`
`"core/client"` → `"core-client.md"`

## Wiki vs Obsidian Vault

| Feature | wiki.py (--wiki) | export.py (--obsidian) |
|---------|-----------------|----------------------|
| Files generated | index + community articles + god node articles | One file per node |
| Scale | ~15-30 files for any corpus size | Thousands of files for large corpora |
| Designed for | AI agent navigation | Human browsing in Obsidian |
| Wikilinks | ✓ | ✓ |
| Cohesion scores | ✓ | ✓ |
| Dataview queries | ✗ | ✓ |
| Canvas layout | ✗ | ✓ |

The wiki is much more compact — it gives an AI agent the highlights without overwhelming it with one file per node. The Obsidian vault is richer but intended for human use.
