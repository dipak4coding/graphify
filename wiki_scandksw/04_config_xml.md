# Config.xml — Configuration File

Tags: #config #xml
Links: [[00_INDEX]] | [[02_architecture]] | [[03_data_structures]]

---

## Purpose

Config.xml is the only thing you need to change to run ScanDKSW on a different project variant. It tells the tool:
- Where the source code lives
- Which compiler switches are active for this variant
- Which files/groups/defines to ignore in the output
- Where to write the output files

---

## Full File Structure

```xml
<ScanDKSW>
  <DasProjekt Path="C:\..."/>            <!-- project root -->
  <DieSourcen Path="\03_SwFunktion"/>    <!-- source folder, relative to project root -->
  <DieKommentare Path="Kommentare"/>     <!-- free-comment files folder -->

  <A2L Path="\99_Output\Target\...a2l"/> <!-- A2L calibration file -->
  <Components Path="\components.DQ_BG3.makelist"/> <!-- top-level makelist -->
  <MakeBat Path="\01_Buildprozess\Make.bat"/>      <!-- compiler batch file -->
  <CTC Path="C:\...\ctc"/>              <!-- compiler executable path (search pattern) -->

  <DestinationFolder Path="\ScanDKSW"/> <!-- output base folder -->
  <Defines_csv        Path="Defines.csv"/>
  <DefinesAll_csv     Path="DefinesAll.csv"/>
  <Doubletten_csv     Path="Doubletten.csv"/>
  <Undefines_csv      Path="Undefines.csv"/>
  <DefMatrix_csv      Path="DefMatrix.csv"/>
  <CAN_csv            Path="CANSignale.csv"/>
  <A2l_csv            Path="A2L.csv"/>
  <VTAB_csv           Path="VTAB.csv"/>
  <METHOD_csv         Path="METHOD.csv"/>
  <TypeDefs_csv       Path="TypeDefs.csv"/>
  <Comments_csv       Path="Comments.csv"/>

  <PreDefines>
    <Define Name="__freeimpl__"/>        <!-- compiler switches active for this variant -->
  </PreDefines>

  <IgnoreDoubletten>
    <Define Name="GSS_GET_P_HAUPT_AKTUELL"/>  <!-- expected duplicates, don't throw -->
  </IgnoreDoubletten>

  <IgnoreGroups>
    <Group Name="version"/>             <!-- exclude these groups from output -->
    <Group Name="bios"/>
  </IgnoreGroups>

  <IgnoreFiles>
    <File Name="tm_dtype.h"/>           <!-- exclude these files from output -->
  </IgnoreFiles>

  <IgnoreDefines>
    <Define Name="KRS_H"/>              <!-- header guards — exclude from output -->
  </IgnoreDefines>

  <SetDeclaration>
    <Declaration Name="const"/>         <!-- values that classify a define as DECLARATION -->
    <Declaration Name="static"/>
  </SetDeclaration>
</ScanDKSW>
```

## Tag-by-Tag Reference

### `<DasProjekt Path="...">`

The **project root** — an absolute path. All other relative paths are resolved from here.

```csharp
dasProject = Item.Attributes["Path"].InnerText;
```

Example: `C:\_2_SOURCEN\sourcen.iav\DQ_BG3.wor\DQ_BG3_A00B08`

### `<DieSourcen Path="\03_SwFunktion">`

The **source folder** — relative to `DasProjekt`. This is where the software components live.

```csharp
dieSourcen = myPathConcat(dasProject, Item.Attributes["Path"].InnerText);
// result: C:\...\DQ_BG3_A00B08\03_SwFunktion
```

### `<DieKommentare Path="Kommentare">`

Folder for free-text comment files. These are plain text files that add annotations to defines. Loaded into `D_Comments`.

### `<A2L Path="\99_Output\Target\DKSW_DQ_BG3_work.a2l">`

Path to the ASAP2 calibration file. ScanDKSW uses it to recognise which defines are **variables** (type `E_DEFTYPE.VARIABLE`) — if a define's value exists as a variable name in the A2L, it's a variable reference, not a constant.

If A2L is empty string `""`, the A2L scanner is skipped.

### `<Components Path="\components.DQ_BG3.makelist">`

The top-level makelist — lists all software groups:
```makefile
COMPONENTS = \
    krs\krs \
    svc\svc \
    gsi\gsi \
    ...
```

### `<MakeBat Path="\01_Buildprozess\Make.bat">`

The compiler batch file generated by the build system. ScanDKSW uses it to extract `--include-directory=` paths for each C file — these are the system/platform include paths not visible in the source folders.

```csharp
// extractMaker() looks for:
// "echo ***** Kompiliere und assembliere {filename}"
// then reads the next compiler invocation line
// and extracts "--include-directory=path1,path2,..."
```

### `<CTC Path="C:\...\ctc">`

The compiler executable path used as a search pattern when scanning `Make.bat`. The tool looks for lines starting with this string to find the compiler invocation.

### `<DestinationFolder Path="\ScanDKSW">`

Output base folder. Relative to `DasProjekt`. Three sub-folders are created automatically:
- `{DestPath}\.bins\` — binary cache files
- `{DestPath}\.csvs\` — CSV output files
- `{DestPath}\Comments\` — comments output

### CSV path tags

All CSV paths (`<Defines_csv>`, `<DefinesAll_csv>`, etc.) are relative to `{DestPath}\.csvs\`.

```csharp
define_csv = myPathConcat(CsvFilePath, Item.Attributes["Path"].InnerText);
// CsvFilePath = DestPath + "\.csvs"
```

### `<PreDefines>`

These are compiler switches that are **defined but have no value** — just their presence in `D_Defines` makes `#ifdef MY_SWITCH` evaluate to true.

```csharp
// For each <Define Name="...">:
D_Defines.Add(preDef, new define(preDef, "", "-Config.xml", 0));
```

Note: the `position` is set to `"-Config.xml"` and line `0` — a special marker so you can tell pre-defined switches apart from source-defined ones.

**Typical PreDefines** (for DQ381G4 variant):
```xml
<PreDefines>
  <Define Name="CS_MODUS_DERIVAT_DQ381G4"/>
  <Define Name="__freeimpl__"/>
</PreDefines>
```

These switches control which `#ifdef` branches are "alive" vs "dead code".

### `<IgnoreDoubletten>`

Some defines are legitimately declared in multiple places (e.g. in a shared header included by two groups). If their values are different, ScanDKSW would normally throw an exception (`"Define X is double defined!"`). Adding them here suppresses the exception.

```csharp
if (IgnDoubletten.Contains(d)) {
    myWriteLine("doppelte Definition von >" + d + "< wird ignoriert!");
}
else {
    throw new Exception("Define >" + d + "< ist doppelt definiert!");
}
```

### `<IgnoreGroups>`, `<IgnoreFiles>`, `<IgnoreDefines>`

These are **output filters** — they don't affect scanning or findings collection. They're applied when writing the filtered `Defines.csv` (as opposed to `DefinesAll.csv` which contains everything).

Example: `version`, `bios`, `iavlib` groups contain platform/toolchain code, not application logic. You don't want them cluttering the interface matrix.

### `<SetDeclaration>`

Values that should classify a define as `E_DEFTYPE.DECLARATION`:
```xml
<SetDeclaration>
  <Declaration Name="const"/>
  <Declaration Name="static"/>
  <Declaration Name="extern"/>
  <Declaration Name="inline"/>
</SetDeclaration>
```

Example: `#define KRS_EXTERN extern` → value is `"extern"` → type = DECLARATION.

## `readConfig()` — How It's Parsed

Located in `Tools.cs`. Uses `XmlDocument` and `SelectSingleNode()`:

```csharp
XmlDocument doc = new XmlDocument();
XmlReaderSettings settings = new XmlReaderSettings();
settings.IgnoreComments = true;  // strip XML comments
StreamReader sr = new StreamReader(a_cnfgxml);
XmlReader reader = XmlReader.Create(sr, settings);
doc.Load(reader);

Root = doc.SelectSingleNode("ScanDKSW");
Item = Root.SelectSingleNode("DasProjekt");
dasProject = Item.Attributes["Path"].InnerText;
```

Path concatenation uses `myPathConcat()`:

```csharp
static string myPathConcat(string Directory, string Path)
{
    if (!Path.Contains(":"))       // not an absolute path?
        if (Path.StartsWith("\\") || Path.StartsWith("/"))
            Path = Directory + Path;         // absolute-relative: just concat
        else
            Path = Directory + "\\" + Path;  // relative: add separator
    return Path;
}
```

This handles both `\03_SwFunktion` (leading backslash) and `Kommentare` (no leading separator).

## Config_DQ381G4.xml

There's a second config file `Config_DQ381G4.xml` in the repository. It's a variant config — same structure as `Config.xml` but with:
- Different `<DasProjekt>` path
- Different `<PreDefines>` (the DQ381G4-specific compiler switches)
- Possibly different `<Components>` makelist

You switch variants by passing a different `-config=` argument. No code changes needed.
